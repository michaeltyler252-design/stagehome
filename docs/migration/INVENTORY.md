# StageHome Backend — Complete Feature Inventory (Pre-Migration)

Generated by direct inspection of the current codebase (`apps/api/src`,
`packages/database/prisma/schema.prisma`, `apps/worker/src`). Every item
below is real and currently present — nothing here is aspirational.

## 3. Authentication & Authorization

- **Password auth**: argon2 hashing (`argon2` package)
- **JWT**: short-lived access tokens (15 min) + long-lived refresh tokens (30 days), refresh tokens stored **hashed** (SHA-256) in a `UserSession` table (never plaintext) — supports per-session revocation
- **Google OAuth 2.0**: via `passport-google-oauth20`
- **Phone OTP**: `otplib`-backed, for phone verification pre-booking
- **Admin MFA**: separate TOTP-based flow (`otplib`) for admin accounts specifically
- **Roles/Permissions**: many-to-many `Role`↔`Permission` via `RolePermission`, and `User`↔`Role` via `UserRole`. Roles seeded: Tenant, Manager, Admin, etc. Guarded via `@Roles()` decorator + `RolesGuard`
- **Rate limiting**: custom `RateLimitGuard` + `@RateLimit()` decorator (Redis-backed)
- **CORS**: explicit `WEB_APP_ORIGIN` allowlist + pattern-matched `stagehome*.vercel.app` origins (see `common/cors-origin-matcher.ts`)

## 5. Background jobs / worker

`apps/worker` — a separate Node process using **BullMQ** + **ioredis**. Currently a **scaffold only** (Milestone 1 scope): the process boots and connects, but no real queues are registered yet. The intended real queues (per the scaffold's own comment) are: booking-hold expiry, payment-callback reconciliation, notification dispatch, media processing — none of these exist as working code today.

## 6. Integrations

- **M-Pesa / Safaricom Daraja** — `DarajaClient` (STK push initiation + callback handling), no real credentials configured yet (documented gap)
- **Google OAuth** — real, via passport strategy
- **Sentry** (`@sentry/node`) — error monitoring
- **Email/SMS/WhatsApp** — `NotificationsService` with pluggable clients (email, SMS, WhatsApp clients exist with tests)
